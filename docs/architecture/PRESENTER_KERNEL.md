# OmniVyx Vision Presenter Kernel

OmniVyx Vision is a live, AI-directed visual performance environment. The presenter and the AI author, rehearse, and perform a scored cinematic show together.

The native Presenter Kernel is the authority boundary between perception systems and the visual stage.

## Runtime Path

```text
native audio capture
  -> streaming transcript
  -> semantic intent candidates
  -> show-context arbitration
  -> validated presenter signal
  -> deterministic show transition
  -> WebGL stage render
```

## Invariants

1. The semantic engine proposes intent; it does not directly mutate the stage.
2. The show runtime remains deterministic for a given show document and accepted signal sequence.
3. Every accepted presenter signal receives a monotonically increasing native sequence number.
4. Presentation-time improvisation is bounded by the visual grammar and dynamic slots authored before the show.
5. Native speech, local models, and cloud models are adapters behind stable contracts rather than dependencies of stage components.
6. The browser build remains functional as a fallback, but it does not define the quality ceiling of the native presenter.

## Current Kernel Contract

Tauri exposes two commands:

- `get_presenter_capabilities`: reports the native shell, platform, architecture, and subsystem readiness.
- `accept_presenter_signal`: validates a typed signal and returns a sequenced receipt.

Supported signal kinds are:

- `transcriptFinal`
- `intentCandidate`
- `manualCue`
- `hold`
- `resume`

The current React proof submits transcript or intent signals through this contract. In a browser, the bridge resolves to a no-op fallback. In the Tauri app, Rust accepts and sequences the signal.

## Cinematic Show Document

`src/visual-engine/cinematicScore.ts` is the versioned visual contract for the current launch performance. Every accepted stage event resolves to one cue containing:

- authored copy and semantic emphasis;
- camera position, target, field of view, transient shot arc, focal arc, roll, and portrait framing;
- bounded idle, minimum, maximum, energy, and peak pacing targets;
- product core, organic system, dynamic slot, glass, and hybrid-media composition targets;
- key, rim, and accent light levels;
- atmosphere glow position, horizon, ribbons, evidence grid, particles, and drift;
- bloom, depth focus, bokeh, vignette, and exposure targets;
- continuous motion energy.

Stage components consume those targets with frame-rate-independent exponential damping. Cue handlers never mutate Three.js objects directly and render-loop code does not allocate target vectors per frame.

The visual grammar is cue-directed rather than globally decorative. Each cue authors a palette plus hero position, scale, and yaw. Product, network, and dynamic-data moments enforce a single dominant actor so supporting geometry yields instead of accumulating. The current premium material set consists of a four-draw optical core, one seven-plane instanced liquid-glass array, palette-driven procedural cloth, a two-draw-call organic constellation, and a two-draw-call cinematic evidence actor. The cloth keeps a fixed two-draw contract: foreground and background sheets use layer-specific macro folds, diagonal pleats, analytic folded normals, anisotropic warp-and-weft glints, dual specular lobes, and thin-film palette shifts. A separately damped presenter-energy uniform lifts the material response without recreating geometry or competing with the deliberately quiet hold cue. The optical core combines one thin iridescent shell, one recessed procedural iris surface, one suspended faceted lens, and one instanced draw containing eight rounded perimeter rails. The iris synthesizes a layered cavity, segmented aperture, depth disc, micro-traces, radial ticks, and moving caustics in one fragment pass. Shell roughness and iridescence, rail assembly, lens rotation, palette, and emissive response follow the same damped cue and presenter-energy bus without render-loop allocation. The product cue uses the full authored portrait pullback and a hero-biased focal target so the complete optical instrument remains visible beside the narrative copy at narrow aspect ratios. Live direction turns the core to expose its depth; hold makes it the sole quiet actor and drops the dormant network. The optical array shares one subdivided geometry and one shader material; seven persistent transform composers update one dynamic instance-matrix buffer, giving the stage more varied scale, depth, drift, and impact response while replacing three draw calls with one. The constellation expands its authored skeleton into a deterministic 61-node, 60-edge canopy, then builds one curved ribbon geometry and one node geometry at mount time. A tested width function gives the base a substantial root and tapers continuously toward the branch tips. The ribbon shader combines twisted depth, inner conduction, rim light, fine striation, traveling presenter-energy pulses, and a bright growth frontier so the structure grows from root to canopy instead of appearing as one graph. The existing point pass renders small junction lenses and larger rotated terminal leaf lenses with faceted color, central and forked veins, frontier bloom, and the same branch sway. GPU growth masks reveal both buffers without render-loop allocation or extra draws. The evidence actor uses one four-column instanced mesh and one fixed tube curve. Its matrices, reveal mask, palette, and voice response animate existing buffers, and its faster release envelope removes both draws after the editorial handoff. Dormant organic and product actors now leave the draw path after their damped scale and opacity fall below visibility thresholds, preventing pixel residue while returning the network's two-draw budget to compositions that do not need it.

Lighting is an authored part of the cinematic show document rather than a global renderer preset. Every cue scores ambient fill, a normalized focal position and radius, beam strength, and negative-space protection alongside the existing key, rim, and accent levels. The same values steer a moving three-light rig and a screen-aware focal pool with diagonal volumetric shafts inside the existing one-draw world shader. Portrait presentation remaps the focal target above the copy, while a cue-scaled media mask and zero-draw compositing matte protect the complete copy region from later transparent layers. Presenter level and peak lift the local pool and shafts, emphasis adds a short key, rim, and accent strike, and cadence adds a restrained sustained lift. All channels use persistent damped uniforms without changing the authored resting hierarchy or allocating in the render loop.

Prepared dynamic content now has one shared evidence contract. `src/visual-engine/evidenceScore.ts` owns the exact series metadata, values, display labels, and normalization used by both the WebGL actor and the accessible DOM readout. The readout is open editorial typography rather than a dashboard card: its KPI resolves as four independently masked glyphs under one accessible metric label, and each year grows a proportional rule from the same normalized value used by its GPU column. Reduced-motion environments resolve both layers immediately. The two-draw evidence actor keeps its instanced columns and fixed tube curve while adding one damped presenter-energy uniform to each persistent shader; voice subtly accelerates column scans and curve pulses while raising cap and pulse light without recreating materials or allocating in the render loop. The runtime exposes evidence activity and point count for audits, and direct evidence-to-resolve transitions preserve the prepared slot while other cue paths yield it.

Semantic transitions and vocal performance are separate control channels. An accepted intent changes the deterministic stage event. Presenter level, peak, emphasis, learned cadence, and a manual fallback impulse may affect camera, lighting, cloth, glass, copy, and hero motion, but none can mutate the active event. Cue arrival, impact, and overshoot values plus those five bounded vocal channels live on one stable mutable motion bus, keeping choreography synchronized without React state updates or render-loop allocations.

An accepted intent can interrupt a cue without restarting the stage from rest. The director samples the unfinished cue once, carries a bounded continuity value into the next score, and decays that value independently of frame rate. While continuity is active it gives camera, media, lighting, and actors enough damping to move from their current transforms toward the new authored targets, while reducing the new cue's impact and overshoot. Repeated commands preserve the strongest unfinished handoff, never stack visual actors, and expose `data-cue-handoff` plus `data-cue-interrupted` for runtime audits. Interrupted typography uses a compressed handoff profile with a shorter outgoing tail and earlier legibility; uninterrupted cues retain their full authored copy delay and reveal.

Continuous presenter performance enters through a second stable mutable signal. The browser/native-webview proof requests a mono microphone stream, reuses one 512-sample PCM buffer and measurement object, and derives level, peak, emphasis, and cadence with scalar frame-rate-independent envelopes. Emphasis compares a fast vocal attack against a slow baseline, uses an onset gate to prevent sustained vowels from retriggering, and decays as a short accent. Cadence learns the interval and regularity of rearmed onsets, bridges the short silences between words, and releases after the phrase goes stale. Camera breathing, media refraction, cloth energy, glass, product highlights, the organic constellation, cue-authored atmosphere, kinetic copy, and cinematic lighting consume those channels without React state updates, FFT work, or per-frame allocations. A manual cue or finalized transcript emits a bounded 220 ms level, peak, and emphasis kick only when waveform capture is inactive; runtime attributes distinguish that fallback (`audio: idle`) from a real microphone signal (`audio: active`) and expose all four analyzed values for audit. Recognition sessions keep current show context in a ref so relative commands are never evaluated against the state from when listening began.

The macOS bundle declares microphone and speech-recognition usage descriptions. The native audio-energy surface is implemented as Web Audio hosted in WKWebView but remains `planned` until microphone device preflight and capture are verified in the packaged app. A future Core Audio adapter can write the same signal contract without changing the stage. Streaming transcription remains planned behind the separate Apple SpeechAnalyzer adapter.

## Render Quality Contract

High quality is adaptive rather than a fixed pixel ratio. The stage measures sustained frame performance, selects a bounded device pixel ratio, and temporarily regresses resolution during scored transitions. The manual low-quality gate is a deterministic fallback: it removes the adaptive-DPR controller, fixes renderer DPR at `1.0`, disables post-processing, and fades the media plate out of the draw list.

The operator preview uses a stable aspect ratio. Presentation view expands the same stage to the full native window, hides operator controls and telemetry, advances authored cues with left and right arrow keys, and exits with Escape. Speech and native semantic signals continue to use the same event path in both views.
